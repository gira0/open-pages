# API reference

This page lists every HTTP route the server registers, with its authentication
requirement, request and response shapes and status codes, with `curl` examples for the main
workflows (not for every route). Who may do what
is explained in [auth.md](auth.md); the tables behind the data are in [schema.md](schema.md).

The `curl` examples assume the server is at `https://pages.corp`. `cookies` is a cookie jar
file written by the login call, and `$OPEN_PAGES_TOKEN` holds an API token.

## Conventions

- **Format.** API responses are JSON (`Content-Type: application/json`). Request bodies are
  JSON unless stated otherwise and are limited to 64 KiB (uploads have their own limit).
- **Errors.** Errors from the JSON routes are `{"error": "<message>"}` with the status code
  listed below. Their 500 responses say `{"error": "internal error"}`; the cause goes to the
  log, tagged with the request ID. Unknown paths, wrong methods (405) and served-site errors
  are plain-text responses, not JSON.
- **Request ID.** Every response carries an `X-Request-Id` header generated by the server
  (an incoming one is ignored). The same ID appears in the log lines for that request.
- **Authentication.** Two credentials exist:
  - a **session cookie** (`auth_cookie`, 7 days) from `POST /v1/user/login` or OIDC sign-in;
  - an **API token** (`opt_...`) sent as `Authorization: Bearer <token>`.

  In the tables below, "any" means either one, "session" means a session cookie only (an
  API token gets 401 there), and "none" means no credential. A request that carries an
  `Authorization: Bearer` header is judged on the token alone and never falls back to the
  cookie. A rejected session cookie is cleared with a `Set-Cookie` that expires it.
  Missing or invalid credentials give `401 {"error":"unauthenticated"}` on "any" routes and
  `401 {"error":"a login session is required"}` on "session" routes.
- **CORS.** With no `cors_origins` configured no CORS headers are sent (same-origin only).
  For a listed origin the server answers with `Access-Control-Allow-Origin` (that origin),
  `Access-Control-Allow-Credentials: true`, and handles `OPTIONS` preflights with `204`.
- **Ids.** Group, member and token ids are positive integers. A non-numeric or non-positive
  id in a path is a 404 for that kind of object.
- **Optional routes.** Four route groups exist only when configured: `/metrics` (needs
  `[metrics] token`), the register and login routes (not registered when
  `[auth] local_login = false`), and the two OIDC routes (only with `[oidc] enabled = true`).
  A route that is not registered answers 404 or 405 like any unknown path.

## Service routes

### GET /v1/ping

No authentication. Always `200 {"message":"pong"}`; it touches nothing.

```sh
curl https://pages.corp/v1/ping
```

### GET /healthz

No authentication, so load balancers and orchestrators can probe it. It pings the database
and checks that the site directory (`<datapath>/op_data`) and the staging directory
(`<tmppath>/tmp`) accept new files, giving up after 2 seconds. The response never says why
a check failed; the reason is logged at `warn`.

- `200 {"status":"ok","checks":{"database":"ok","data_dir":"ok"}}`
- `503 {"status":"fail","checks":{"database":"fail","data_dir":"ok"}}` (any check failed)

Responses carry `Cache-Control: no-store`.

### GET /metrics

On the main listener it is registered only when `[metrics] token` is set, and then requires
`Authorization: Bearer <metrics token>` (the metrics token from `settings.ini`, not an API
token). On the dedicated listener (`[metrics] listen`) it is always registered; it requires
the same header only if a token is configured, and is open to anyone who can reach the
address otherwise.

- `200` Prometheus text format, `Content-Type: text/plain; version=0.0.4`.
- `401 {"error":"metrics token required"}` with `WWW-Authenticate: Bearer`.

The dedicated listener serves `/metrics` and nothing else. The metric names are listed in [getting-started.md](getting-started.md#metrics).

```sh
curl -H "Authorization: Bearer $METRICS_TOKEN" https://pages.corp/metrics
```

### GET /index

No authentication. Renders `cmd/open-pages/templates/index.html`: a local login form (when local login is
enabled), a "Sign in with your company account" link (when OIDC is enabled) and a form that
creates a site and uploads an archive to it. It is a test page, not a stable interface.

### GET /v1/sites

No authentication. Lists the sites whose visibility is `public`, ordered by name.
`authenticated` and `restricted` sites never appear here.

`200`:

```json
{"sites": [{"name": "blog", "description": "Team blog"}]}
```

```sh
curl https://pages.corp/v1/sites
```

## Accounts and sessions

### POST /v1/user/register

Auth: none. Not registered when `[auth] local_login = false`.

Body: JSON `{"email": "...", "password": "..."}` or an HTML form with the same field names.
The email must be a bare address (`user@example.com`, no display name); the password must be
8 to 72 bytes (bcrypt ignores more).

| Status | Body |
|---|---|
| 201 | `{"status":"user created"}` |
| 400 | `{"error":"invalid email"}`, `{"error":"password must be 8 to 72 characters"}`, `{"error":"invalid JSON body"}` or `{"error":"invalid form body"}` |
| 409 | `{"error":"user already exists"}` |

Registration is open: anyone who can reach the server can create an account. The email
uniqueness check is case-sensitive for local accounts.

```sh
curl -X POST https://pages.corp/v1/user/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"ada@corp.example","password":"correct horse"}'
```

### POST /v1/user/login

Auth: none. Not registered when `[auth] local_login = false`. Same body as register.

| Status | Body |
|---|---|
| 200 | `{"status":"successful login"}` and `Set-Cookie: auth_cookie=...` |
| 400 | as for register |
| 401 | `{"error":"invalid email or password"}` (unknown email, wrong password, or an OIDC-only account) |

The cookie is `HttpOnly`, `SameSite=Lax`, `Path=/`, lives 7 days, and has the `Secure` flag
when `cookie_secure = true`.

```sh
curl -c cookies -X POST https://pages.corp/v1/user/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"ada@corp.example","password":"correct horse"}'
```

### POST /v1/auth/logout

Auth: session. Deletes the session row and clears the cookie.
`200 {"status":"logged out"}`; `401` without a valid session.

```sh
curl -b cookies -X POST https://pages.corp/v1/auth/logout
```

### GET /v1/auth/user

Auth: any. Returns the caller's account, groups and sites.

`200`:

```json
{
  "userid": 1,
  "email": "ada@corp.example",
  "groups": [{"id": 3, "name": "Eng", "owner_id": 1}],
  "docs": {
    "owned":    [{"id": 7, "name": "blog", "description": "", "owner_id": 1, "group_id": 3}],
    "viewable": [{"id": 7, "name": "blog", "description": "", "owner_id": 1, "group_id": 3}]
  }
}
```

- `groups` are the groups the caller belongs to, by name.
- `docs.owned` are the caller's own sites ("docs" is the table name for sites).
- `docs.viewable` are the sites the caller owns, plus every `authenticated` site, plus
  sites whose group the caller shares with the site owner (so a `restricted` site shows up
  for its group's members, and so does a `public` one that has a group). A `public` site
  without a group that someone else owns is not in this list: public sites are listed by
  `GET /v1/sites`.
- `owner_id` and `group_id` are `null` when absent. The list entries carry no visibility.

`401` when unauthenticated.

```sh
curl -H "Authorization: Bearer $OPEN_PAGES_TOKEN" https://pages.corp/v1/auth/user
```

## OIDC sign-in

Both routes exist only when `[oidc] enabled = true`; setup is in [auth.md](auth.md#oidc-sign-in).

### GET /v1/auth/oidc/login

Auth: none. Optional query `return_to`: a path on this server (starts with a single `/`, at
most 512 bytes, no backslash or line breaks) to land on afterwards.

| Status | Meaning |
|---|---|
| 302 | Redirect to the identity provider; sets the short-lived `oidc_state` cookie (`Path=/v1/auth/oidc`, 10 minutes) |
| 400 | `{"error":"return_to must be a path on this server"}` |
| 502 | `{"error":"identity provider unavailable"}` (discovery failed) |
| 503 | `{"error":"too many sign-in attempts, try again later"}` (10000 attempts pending) |

### GET /v1/auth/oidc/callback

Auth: none. This is the URL registered at the provider as the redirect URI. It expects the
`state` and `code` query parameters and the `oidc_state` cookie.

| Status | Meaning |
|---|---|
| 200 | `{"status":"successful login"}` plus the `auth_cookie` session cookie (no `return_to`) |
| 303 | Redirect to the `return_to` given at login, plus the session cookie |
| 400 | `{"error":"unknown or expired login attempt"}`: state missing, not matching the cookie, already used, or older than 10 minutes |
| 401 | `{"error":"sign-in refused by the identity provider"}` (provider sent `error` or no `code`), or `{"error":"the identity provider's response was not accepted"}` (ID token failed verification) |
| 403 | `{"error":"the identity has no usable email address"}` or `{"error":"email domain is not allowed"}` |
| 409 | `{"error":"an account with this email already exists; it is not linked automatically, ask an administrator"}` |
| 502 | `{"error":"identity provider unavailable"}` (discovery, token exchange failed) |

## API tokens

Session only: an API token cannot create, list or revoke tokens.

### POST /v1/auth/tokens

Body: `{"name": "ci", "expires_in_days": 90}`. `name` is required, at most 64 bytes.
`expires_in_days` is optional: 0 or absent means the token never expires, otherwise 1 to
3650.

| Status | Body |
|---|---|
| 201 | the token, once (see below); response has `Cache-Control: no-store` |
| 400 | `{"error":"invalid JSON body"}`, name missing or too long, or `expires_in_days` out of range |
| 401 | `{"error":"a login session is required"}` |
| 409 | `{"error":"token limit reached; revoke one first"}` (50 tokens per user; expired ones do not count) |

```json
{"id": 1, "name": "ci", "prefix": "opt_e0798fff", "created": "2026-10-09T19:02:35Z",
 "expires": "2026-11-08T19:02:35Z", "token": "opt_e0798fff10..."}
```

`expires` is `null` for a token without expiry. The full `token` value is returned only in
this response; the server keeps a SHA-256 hash and the `prefix`.

```sh
curl -b cookies -X POST https://pages.corp/v1/auth/tokens \
  -H 'Content-Type: application/json' -d '{"name":"ci","expires_in_days":90}'
```

### GET /v1/auth/tokens

`200 {"tokens":[{"id":1,"name":"ci","prefix":"opt_e0798fff","created":"...","expires":null}]}`,
ordered by id, caller's tokens only. Never contains the token itself.

### DELETE /v1/auth/tokens/{id}

`200 {"status":"token revoked"}`. `404 {"error":"token not found"}` for an unknown id and
also for another user's token.

## Groups

All group routes accept any credential. See [auth.md](auth.md#groups) for the rules.

### POST /v1/auth/groups

Body `{"name": "Eng"}`: 1 to 64 characters after trimming, no control characters. The
caller becomes owner and first member.

| Status | Body |
|---|---|
| 201 | `{"id":3,"name":"Eng","owner_id":1}` |
| 400 | `{"error":"invalid JSON body"}` or `{"error":"name must be 1 to 64 characters without control characters"}` |
| 409 | `{"error":"a group with that name already exists"}` (names are unique ignoring case) |

```sh
curl -b cookies -X POST https://pages.corp/v1/auth/groups \
  -H 'Content-Type: application/json' -d '{"name":"Eng"}'
```

### GET /v1/auth/groups

`200 {"groups":[{"id":3,"name":"Eng","owner_id":1}]}`: the groups the caller belongs to,
ordered by name. `owner_id` is `null` for groups that predate owners.

### GET /v1/auth/groups/{id}

Members only.

- `200 {"id":3,"name":"Eng","owner_id":1,"members":[{"id":1,"email":"ada@corp.example"}]}`
  (members ordered by email)
- `403 {"error":"you are not a member of this group"}`
- `404 {"error":"group not found"}`

### DELETE /v1/auth/groups/{id}

Owner only; deletes the group and its memberships.

- `200 {"status":"group deleted","id":3}`
- `403 {"error":"you do not own this group"}` (also for a group without an owner)
- `404 {"error":"group not found"}`
- `409 {"error":"group is still used by sites; move or delete them first"}`

### POST /v1/auth/groups/{id}/members

Owner only. Body `{"email": "grace@corp.example"}`; the user must already have an account
(the match is exact, including case).

| Status | Body |
|---|---|
| 201 | `{"status":"member added","group":3}` |
| 200 | `{"status":"already a member","group":3}` |
| 400 | `{"error":"body must be JSON with an email"}` |
| 403 | `{"error":"you do not own this group"}` |
| 404 | `{"error":"group not found"}` or `{"error":"user not found"}` |

If the user was a provider-managed member (added by OIDC), adding them by hand turns that
membership into a manual one.

### DELETE /v1/auth/groups/{id}/members/{uid}

`{uid}` is the user id (see the `members` list). The owner may remove any other member; a
member may remove themselves.

| Status | Body |
|---|---|
| 200 | `{"status":"member removed","group":3,"user":2}` |
| 400 | `{"error":"the owner can't be removed from the group; delete the group instead"}` |
| 403 | `{"error":"you do not own this group"}` (caller is neither owner nor the target) |
| 404 | `{"error":"group not found"}` or `{"error":"user is not a member of this group"}` |

## Sites

A site name is a DNS label: 1 to 63 lowercase letters, digits or hyphens, not starting or
ending with a hyphen. These names are reserved in both URL modes and are refused with 400:
`v1`, `index`, `api`, `www`, `admin`, `ui`, `static`, `assets`, `health`, `healthz`,
`readyz`, `metrics`, `login`, `logout`, `register`, `auth`, `user`, `users`, `sites`,
`docs`, `app`, `mail` (`reservedSites` in `internal/names/names.go`).

Whoever creates a site owns it. Routes that change a site, or list or roll back its
versions, are owner-only: `404 {"error":"site not found"}` for an unknown or invalid name,
`403 {"error":"you do not own this site"}` for someone else's site.

### POST /v1/auth/sites

Body:

```json
{"name": "blog", "description": "Team blog", "group": 3, "visibility": "restricted"}
```

`name` is required. `description` is optional, at most 512 bytes. `group` is an optional
group id (0 or absent for none). `visibility` is `public` (default), `authenticated` or
`restricted`.

| Status | Body |
|---|---|
| 201 | `{"status":"site created","name":"blog","visibility":"restricted"}` |
| 400 | invalid JSON, invalid or reserved name, description too long, bad visibility, or `{"error":"group not found"}` |
| 403 | `{"error":"you are not a member of this group"}` (the owner must belong to the group) |
| 409 | `{"error":"a site with that name already exists"}` |

Creating a site does not deploy anything; upload an archive next. Until then the site
answers 404.

```sh
curl -H "Authorization: Bearer $OPEN_PAGES_TOKEN" -X POST https://pages.corp/v1/auth/sites \
  -H 'Content-Type: application/json' \
  -d '{"name":"blog","visibility":"authenticated"}'
```

### GET /v1/auth/sites/{name}

Returns the metadata to anyone who may view the site: any logged-in user for `public` and
`authenticated` sites; the owner and the group's members for `restricted` ones (see
[auth.md](auth.md#site-visibility)).

- `200`:

  ```json
  {"name": "blog", "description": "", "owner_id": 1, "group": 3,
   "visibility": "restricted", "current": "db4jkiu64plctc6e9140"}
  ```

  `group` is 0 when the site has none; `owner_id` is `null` for a site without an owner;
  `current` is `""` before the first deploy.
- `403 {"error":"you may not view this site"}`
- `404 {"error":"site not found"}`

### PUT /v1/auth/sites/{name}

Owner only. Body fields are all optional and absent fields are left unchanged:
`description` (at most 512 bytes), `group` (id; `0` removes the group), `visibility`.

- `200 {"name":"blog","description":"d","group":0,"visibility":"restricted"}`
- `400` invalid JSON, description too long, bad visibility, or `{"error":"group not found"}`
- `403` not the owner, or `{"error":"you are not a member of this group"}`
- `404` site not found

```sh
curl -b cookies -X PUT https://pages.corp/v1/auth/sites/blog \
  -H 'Content-Type: application/json' -d '{"visibility":"public"}'
```

### DELETE /v1/auth/sites/{name}

Owner only. Removes all versions from disk, then the database row.
`200 {"status":"site deleted","name":"blog"}`; `403`; `404`.

### POST /v1/auth/sites/{name}/upload

Owner only. The request body is the archive itself: `.zip`, `.tar.gz` or `.tar`. The format
is detected from the first bytes, so `Content-Type` and file names do not matter. The
archive is extracted into a new version which becomes live atomically.

| Status | Body |
|---|---|
| 200 | `{"status":"File uploaded","site":"blog","version":"db4jkiu64plctc6e9140"}` |
| 400 | unsupported format, corrupt archive, an entry outside the site, more than `max_extract_files` entries or more than `max_extract_mb` uncompressed, or `{"error":"failed to read upload"}` |
| 403 / 404 | not the owner / site not found (also if the site was deleted during the upload) |
| 413 | `{"error":"upload exceeds 100 MiB"}` (the `max_upload_mb` value) |

Symlinks and other special entries in an archive are skipped. Versions beyond
`keep_versions` are deleted after a successful deploy.

```sh
(cd public && zip -qr ../site.zip .)
curl -H "Authorization: Bearer $OPEN_PAGES_TOKEN" -X POST \
  --data-binary @site.zip https://pages.corp/v1/auth/sites/blog/upload
```

### POST /v1/auth/sites/{name}/formupload

Same as `upload`, with the archive in the multipart field `file`. The whole request is
capped at `max_upload_mb` plus 1 MiB. Statuses are those of `upload`, except that a missing
field, a malformed multipart body or a request over the cap is
`400 {"error":"missing or invalid file field"}` rather than 413.

```sh
curl -b cookies -F file=@site.zip https://pages.corp/v1/auth/sites/blog/formupload
```

### GET /v1/auth/sites/{name}/versions

Owner only. Versions kept on disk, newest first, and the live one:

```json
{"site": "blog", "current": "db4jkiu64plctc6e9140",
 "versions": ["db4jkiu64plctc6e9140", "db4jkiu64plctc6e912g"]}
```

Version ids are 20-character time-sortable ids (xid). `current` is `""` and `versions` is
empty before the first deploy.

### POST /v1/auth/sites/{name}/rollback

Owner only. Body `{"version": "db4jkiu64plctc6e912g"}` makes that kept version live.

- `200 {"status":"rolled back","site":"blog","version":"db4jkiu64plctc6e912g"}`
- `400 {"error":"body must be JSON with a version id"}`
- `403` / `404` not the owner / site not found, or `{"error":"version not found"}` (not on disk, pruned, or not a valid id)

```sh
curl -b cookies -X POST https://pages.corp/v1/auth/sites/blog/rollback \
  -H 'Content-Type: application/json' -d '{"version":"db4jkiu64plctc6e912g"}'
```

## Serving sites

Deployed sites are served over `GET` and `HEAD`; where depends on `[sites] url_mode`.

| url_mode | Site URL | Everything else |
|---|---|---|
| `path` (default) | `https://pages.corp/<site>/<file>` | API, UI and probes on the same host; the reserved names cannot be sites |
| `subdomain` | `https://<site>.pages.corp/<file>` | Hosts that are not under `base_domain` reach the API and UI routes only; there is no site fallback. Other methods on a site host: `405` with `Allow: GET, HEAD` |

Behaviour in both modes:

- A directory serves its `index.html`; `/docs` redirects to `/docs/` with `301`; there are
  no directory listings. `/file.html/` is a 404.
- A missing file serves the site's `404.html` with status 404 if the version has one,
  otherwise a plain `404 page not found`.
- `Content-Type` comes from the file extension; `ETag` (weak, includes the version),
  `Last-Modified`, conditional and range requests work. Public sites send
  `Cache-Control: no-cache` so a deploy or rollback shows up at once.
- Files are opened through `os.Root`: `..` segments are cleaned and symlinks inside a site
  that point outside it are refused.
- A site that does not exist, has never been deployed, or that the viewer may not see is a
  plain 404. For non-public sites the response is identical for "missing" and "not allowed"
  (`Cache-Control: no-store`), and everything served for a non-public site carries
  `Cache-Control: private, no-cache` and `Vary: Cookie, Authorization`.
- Non-public sites accept the session cookie or an `Authorization: Bearer` API token. In
  subdomain mode the session cookie does not reach `<site>.<base_domain>` (see
  [auth.md](auth.md#known-limits)), so only API tokens work there:

```sh
curl -H "Authorization: Bearer $OPEN_PAGES_TOKEN" https://blog.pages.corp/
```
